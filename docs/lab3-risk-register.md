# Lab 3 Risk Register

This register is a draft for the university MVP implementation plan. Priorities are planning judgments, not measured probabilities or formal service targets.

| ID | Risk | Symptoms | Consequences | Detection | Mitigation | Priority | Responsible role |
|---|---|---|---|---|---|---|---|
| RISK-001 | Feature work starts before PLAN-GATE approval | Issue #3 has no Student `GO`, but a Feature is marked in progress | Work may diverge from the approved plan | Review Issue #3 before starting any Feature | Keep #3 as a hard prerequisite; Student records `GO` or `REVISE` | High | Student |
| RISK-002 | Agent introduces excluded manual ingredient entry | Free-text ingredient input appears in implementation or tests | Violates REQ-F-023 and approved MVP scope | Review changes against REQ-F-023 and Issue #7 | Use the fixed catalog only; reject scope expansion during review | High | Coding Agent, Student |
| RISK-003 | Agent adds singular/plural normalization after it was excluded | `tomato` and `tomatoes` are automatically equated without an approved decision | Contradicts the closed Issue #4 decision | Inspect matching behavior and related tests | Treat standardized catalog identity as authoritative; require Addendum for any change | High | Coding Agent, Student |
| RISK-004 | Requirements are implemented but traceability is incomplete | Feature evidence lacks exact REQ or AC references | Verification cannot show baseline coverage | Review Issue source sections and final matrix | Preserve exact IDs and add approved Issue links only after review | Medium | Shared |
| RISK-005 | BDD coverage is overstated | A ticket claims BDD coverage where traceability records no direct scenario | Verification evidence becomes misleading | Compare claims with `spec/traceability.md` | Mark absent mappings as unconfirmed; use AC or inspection methods instead | High | Shared |
| RISK-006 | Permissions are implemented inconsistently | Visitor can perform Registered User actions, or a user edits another user's content | Violates REQ-F-001-003, REQ-F-018, REQ-F-021, and photo permissions | Test both allowed and forbidden role/ownership paths | Review permissions across Issues #5, #6, and #9 before acceptance | High | Coding Agent, Student |
| RISK-007 | Matching uses ingredient quantities | Search compares required quantity with user quantity | Contradicts REQ-F-026 and REQ-F-031 | Use matching examples with different quantities | Match catalog availability only; verify with the BDD search scenarios | High | Coding Agent, Student |
| RISK-008 | Recipe validation is incomplete | Invalid recipe or edit is saved, or the previous valid version is lost | Violates REQ-F-010-019 and AC-006-010 | Exercise invalid names, ingredients, quantities, units, steps, and edits | Keep validation within Issue #6 and require evidence before closure | High | Coding Agent, Student |
| RISK-009 | Destructive photo or recipe actions lack confirmation | Removal occurs immediately or cancellation changes data | Violates REQ-F-021-022, REQ-F-040, REQ-F-045 | Review deletion/removal flows | Require explicit confirmation and cancellation checks in Issues #6 and #9 | High | Coding Agent, Student |
| RISK-010 | AI-generated implementation over-engineers the MVP | Unapproved architecture, infrastructure, roles, or social features appear | Increases scope and conflicts with project instructions | Review changed files and Issue scope before acceptance | Apply the university-MVP constraint and Student review | Medium | Coding Agent, Student |
| RISK-011 | Failed updates leave partial data | Recipe/photo operation changes only part of the persisted state | Violates REQ-NF-008 | Test failed recipe and photo operations and inspect resulting state | Treat failure as atomic from the user's perspective; verify in Issues #6 and #9 | High | Coding Agent, Shared |
| RISK-012 | Verification is declared complete without human review | Issue #10 is closed with only agent output | Baseline compliance is not independently accepted | Check Student review evidence before closure | Student accepts Issue #10 evidence; agent cannot close the verification decision alone | High | Student |
| RISK-013 | Schedule estimates are treated as commitments | Delays are hidden or estimates are reported as measured effort | Planning becomes misleading | Compare actual effort with estimates after work | Label all durations as estimates and record actual effort separately | Low | Shared |
| RISK-014 | Existing artifact inconsistencies are silently corrected | `idea.md` or stale traceability wording changes during implementation | Approved Lab 2 baseline is modified without review | Compare changes with baseline and gate records | Keep findings documented; require separate Student-approved documentation work | Medium | Student |
| RISK-015 | Photo behavior is conflated between photo types | Recipe photo permissions are applied to cooked-dish photos, or vice versa | Violates REQ-F-039-045 | Review each photo type separately | Keep photo flows separate in Issue #9 and verify ownership rules | High | Coding Agent, Student |
